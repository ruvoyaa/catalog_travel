# Admin Workflow

## Вход
- URL: `/admin`
- После открытия защищённого URL пользователь попадает на страницу входа.
- После успешной авторизации открывается dashboard с основными разделами админки.

## Основные разделы

### Обзор
- Показывает общее количество туров.
- Показывает количество опубликованных туров.
- Показывает количество категорий.
- Показывает количество поисковых записей.

### Категории
- Используются для типизации туров и фильтрации на публичном сайте.
- Для категории задаются:
  - название;
  - slug.

### Туры
- Основной рабочий раздел для контент-менеджера.
- Позволяет создавать, редактировать и удалять туры.

## Структура карточки тура в админке

### Основное
- Название.
- Slug.
- Статус: `Черновик` или `Опубликован`.
- Длительность в днях.
- Подпись длительности.
- Основная категория.
- Дополнительные категории.
- Короткое описание.
- Полное описание.

### Фотоальбом
- Можно добавить несколько изображений.
- Для каждого изображения задаются:
  - URL изображения;
  - описание изображения.

### Даты и цены
- Можно добавить несколько выездов.
- Для каждой строки задаются:
  - дата начала;
  - дата окончания;
  - цена;
  - валюта;
  - подпись;
  - флаг активности.

### Маршрут на карте
- Для маршрута задаются:
  - название;
  - широта центра;
  - долгота центра;
  - масштаб карты.

## Базовый сценарий публикации тура
1. Создать или проверить категорию.
2. Создать новый тур.
3. Заполнить блок `Основное`.
4. Добавить фото.
5. Добавить даты и цены.
6. Добавить маршрут.
7. При необходимости использовать AI-блок для черновика текста.
8. Проверить тур на публичной витрине.
9. Перевести в статус `Опубликован`.

## Правила работы со статусами
- `Черновик` — тур не попадает в публичный каталог.
- `Опубликован` — тур доступен в каталоге и карточке тура.

## Что проверять после сохранения
- Верно ли отображаются категории.
- Есть ли обложка и фотогалерея.
- Есть ли активные даты и цены.
- Корректен ли маршрут на карте.
- Открывается ли карточка тура на публичном сайте.
- Находится ли тур по релевантному поисковому запросу.

## Ошибки и валидация
- Форма показывает ошибки и общим блоком, и рядом с конкретными полями.
- Для неполной строки даты и цены система требует довести строку до валидного состояния.
- Для маршрута нужно указывать и широту, и долготу.
- Дата окончания не может быть раньше даты начала.
