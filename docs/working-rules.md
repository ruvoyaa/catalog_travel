# Working Rules

## Core

- analyze before implementation;
- do not invent architecture or missing facts;
- prefer minimal safe changes;
- keep the process traceable;
- communicate with the user in Russian.

## Startup Mode

- this project starts in analysis-first mode;
- implementation begins only after the startup prompt and initial repository context are understood;
- first delivery step is documentation foundation: launch docs, scope boundaries, and stage terms of reference;
- stage system for this project should stay compact: 3-4 substantial stages, not a fragmented chain.

## Documentation Baseline

- keep a short README with goal and scope boundaries;
- keep local context in `.codex/context.md`;
- maintain a master spec for the project;
- keep stage documents explicit, but avoid unnecessary micro-stages.
