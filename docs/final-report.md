# Final Report

## Проект
Тестовое задание выполнено как монорепозиторий `catalog_travel` с разделением на 3 контура: `content`, `admin`, `api`.

- `content`: SSR-витрина на `Vue + Vike + Vite + Tailwind`, каталог туров, карточка тура, фильтры, фотогалерея, карта маршрута, даты и цены.
- `admin`: серверная админка внутри `Laravel`, управление турами, категориями, фото, маршрутами, датами и ценами, ручная генерация draft-описаний, парольная авторизация.
- `api`: публичный JSON API для каталога и карточки тура, базовые фильтры и semantic ranking поверх embeddings.

## Архитектура и причины решений
Backend построен вокруг сущности `Tour` и связанных моделей `TourCategory`, `TourImage`, `TourDatePrice`, `TourRoute`, `TourEmbedding`, `LlmGenerationArtifact`. Это разделяет контентный слой, поисковый слой и LLM-артефакты без смешивания ответственности в одном CRUD.

Админка оставлена внутри Laravel, а не вынесена в отдельный SPA-контур. Для MVP это снижает стоимость поддержки, упрощает авторизацию и ускоряет delivery. Публичный интерфейс вынесен в отдельный SSR frontend, потому что для каталога важны скорость первого рендера, индексируемость и чистый пользовательский UX.

Semantic search реализован как отдельный слой поверх существующего API-контракта. Базовый каталог и фильтры продолжают работать независимо от AI-компонентов, а embeddings и draft generation не ломают content workflow.

## AI Workflow
Разработка велась агентским циклом: `inspect -> patch -> test -> build -> run -> browser check`. Крупные изменения делились на небольшие проверяемые шаги. После каждого функционального блока запускались `php artisan test`, frontend/backend builds и runtime-проверка стенда. Такой workflow выбран вместо больших генеративных изменений, чтобы быстро локализовать регрессии и держать проект в рабочем состоянии на каждом этапе.
