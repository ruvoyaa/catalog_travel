# Final Video Plan

## Цель
Показать за 5 минут не только готовое приложение, но и AI workflow, архитектурное разделение и качество доводки по usability.

## Сценарий на 5 минут

### 1. Вступление — 30 сек
- Показать корень репозитория.
- Коротко обозначить стек: `Laravel + Vue + Vike + Tailwind + PostgreSQL-ready schema + AI search layer`.
- Сразу сказать, что проект разделён на `content`, `admin`, `api`.

### 2. Архитектура — 45 сек
- Открыть `apps/backend`, `apps/frontend`, `docs`.
- Коротко объяснить:
  - `frontend` отвечает за SSR-витрину и UX каталога;
  - `backend` отвечает за admin, API и доменную модель;
  - `docs` фиксируют этапы, решения и рабочие правила.

### 3. Публичный каталог — 75 сек
- Открыть главную страницу.
- Показать подборки, фильтры, карточки туров, hover/animation polish.
- Открыть карточку тура.
- Показать фотогалерею, просмотр фото крупно, даты и цены, карту маршрута.
- Сделать акцент, что это SSR-витрина, а не просто клиентский каталог.

### 4. Админка — 75 сек
- Открыть `/admin/login`.
- Войти в админку.
- Показать dashboard, список туров, редактирование тура.
- Отдельно показать фото, даты и цены, маршрут и парольную защиту.
- Коротко отметить, что админка серверная внутри Laravel для более дешёвого и устойчивого MVP.

### 5. API и AI — 45 сек
- Открыть `/api/tours`.
- Показать, что frontend работает через API-контракт.
- Коротко показать semantic search и упомянуть embeddings.
- Если успеваешь, показать draft generation в админке как LLM-assisted workflow.

### 6. Тесты и AI workflow — 30 сек
- Показать `php artisan test`.
- Сказать, что разработка шла через агентский цикл: `inspect -> patch -> test -> build -> run -> browser check`.
- Подчеркнуть, что AI использовался не как “генератор кода одним блоком”, а как оркеструемый workflow разработки и стабилизации.

### 7. Финал — 20 сек
- Коротко проговорить: `AI environment`, `качество кода`, `usability` закрыты через архитектуру, tests и доводку интерфейса.

## Акценты под критерии оценки

### AI окружение — 50%
- Показать не только результат, но и workflow.
- Сделать акцент на итеративной проверке, тестах, runtime и agent-based delivery.
- Упомянуть, что проект разбивался на этапы и каждый этап закрывался отдельно.

### Качество кода — 35%
- Подчеркнуть разделение на `content / admin / api`.
- Показать доменную модель backend и то, что AI-слой вынесен отдельно.
- Сказать, что semantic search не ломает базовый контракт каталога.

### Usability — 15%
- Показать мобильную и визуальную доводку.
- Показать галерею, подборки, анимации, закрытую админку, более чистую форму редактирования.

## Pre-push Checklist
- Проверить `git status`.
- Убедиться, что нет случайных runtime-файлов, логов и секретов.
- Запустить `php artisan test` в `apps/backend`.
- Запустить `npm run build` в `apps/frontend`.
- При необходимости запустить `npm run build` в `apps/backend`.
- Проверить, что docs содержат итоговый отчёт и видео-план.
- Проверить live-demo вручную: `/`, `/tours/...`, `/admin/login`.
- Только после этого делать `git add` и `git commit`.
