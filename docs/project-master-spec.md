# Catalog Travel — Master Project Specification

## 1. Назначение проекта

Разработать веб-приложение с публичным каталогом туров и административной частью.

Приложение должно помогать:

- публиковать туры;
- удобно просматривать туры;
- фильтровать предложения;
- искать туры в том числе через семантический поиск;
- управлять контентом туров из админки;
- ускорять наполнение каталога с помощью LLM.

Бронирование и оформление заказа в scope первой версии не входят.

## 2. Цели первой версии

Первая версия системы должна обеспечивать:

- публичный каталог туров;
- карточку тура;
- фотоальбом тура;
- описание тура;
- длительность;
- категории или типы тура;
- маршрут на Яндекс Карте;
- несколько вариантов `дата + цена` для одного тура;
- базовые фильтры каталога;
- семантический поиск по турам;
- административную часть для управления контентом;
- ручной запуск LLM-генерации тура в админке;
- SSR для публичной части через `Vike`.

## 3. Технологический стек

### 3.1 Backend

- Laravel
- PHP

### 3.2 Frontend

- Vue
- Vike
- Vite
- Tailwind CSS 4
- UI library с кастомной темой

### 3.3 Data and Infrastructure

- PostgreSQL
- Docker
- monorepo

### 3.4 AI / Search

- любая легковесная модель из Hugging Face для расчёта эмбедингов;
- первая версия семантического поиска работает по заранее рассчитанным эмбеддингам.

## 4. Основные части системы

Система состоит из:

1. публичной части каталога;
2. страницы тура;
3. административной части;
4. подсистемы фильтрации и поиска;
5. подсистемы LLM-assisted генерации контента;
6. файловой и медиа-подсистемы.

## 5. Основные пользовательские сценарии

### 5.1 Публичный пользователь

Пользователь должен иметь возможность:

- просматривать каталог туров;
- фильтровать туры по базовым признакам;
- открывать карточку тура;
- смотреть фотоальбом;
- читать описание;
- видеть длительность и тип тура;
- видеть маршрут на карте;
- видеть доступные варианты дат и цен;
- выполнять семантический поиск по турам.

### 5.2 Администратор

Администратор должен иметь возможность:

- создавать, редактировать и публиковать туры;
- управлять категориями или типами;
- управлять фотоальбомом тура;
- управлять маршрутными данными для карты;
- добавлять несколько вариантов дат и цен для тура;
- сохранять тур в статусах `draft` и `published`;
- вручную запускать LLM-генерацию тура;
- при необходимости редактировать LLM-сгенерированный результат перед публикацией.

Административный интерфейс первой версии реализуется внутри Laravel backend, а не в отдельном SSR frontend приложении.

## 6. Основные сущности

Первая версия доменной модели должна учитывать как минимум:

### 6.1 tours

- id
- slug
- title
- short_description nullable
- full_description nullable
- duration_text
- status
- primary_category_id nullable
- created_at / updated_at

### 6.2 tour_categories

- id
- code or slug
- name
- created_at / updated_at

### 6.3 tour_category_links

Если туру нужны несколько категорий, должна быть связь many-to-many.

### 6.4 tour_images

- id
- tour_id
- file path or media reference
- sort_order
- alt_text nullable
- created_at / updated_at

### 6.5 tour_date_prices

- id
- tour_id
- start_date
- end_date nullable
- price
- currency
- label nullable
- is_active
- created_at / updated_at

### 6.6 tour_routes

Маршрут тура должен хранить данные, достаточные для показа на Яндекс Карте.

Минимально допустим один из вариантов:

- coordinates / polyline / waypoints в JSON;
- либо согласованный map payload, пригодный для frontend rendering.

### 6.7 embeddings

Для semantic search система должна хранить:

- связь с туром;
- embedding vector или согласованное представление;
- версию модели или source marker;
- timestamp пересчёта.

### 6.8 llm_generation_artifacts

Если для контроля генерации потребуется отдельная сущность, допустимо хранить:

- исходный prompt or source input;
- generated draft;
- generation status;
- timestamps.

Эта сущность может быть реализована как отдельная таблица или как согласованная часть admin workflow.

## 7. Публичная часть

Публичная часть первой версии должна включать:

- SSR-рендеринг через `Vike`;
- список туров;
- карточки превью;
- фильтры;
- строку поиска;
- страницу тура;
- фотоальбом;
- блок дат и цен;
- маршрут на карте.

## 8. Фильтрация и поиск

Первая версия должна поддерживать:

- базовые фильтры по типу или категории;
- базовые фильтры по длительности при согласованной модели;
- текстовый ввод пользователя;
- semantic ranking or retrieval по заранее рассчитанным embedding data.

На первой версии не требуется:

- отдельный технический экран мониторинга эмбедингов;
- сложный self-service интерфейс управления индексом;
- онлайн-пересчёт embeddings для каждого пользовательского запроса.

## 9. Административная часть

Первая версия админки должна включать:

- CRUD туров;
- CRUD дат и цен;
- CRUD категорий или типов;
- управление медиа тура;
- управление маршрутными данными;
- статусы `draft` и `published`;
- ручной запуск LLM-генерации.

Технически админка должна жить в Laravel backend слое.

Админка первой версии не обязана включать:

- сложный moderation workflow;
- роли и ACL высокой сложности;
- отдельный техэкран диагностики индексации.

## 10. LLM-генерация

LLM-генерация является частью MVP.

Первая версия должна поддерживать:

- ручной запуск генерации из админки;
- получение чернового текста тура;
- возможность доработать результат вручную;
- сохранение итогового текста в основной карточке тура или в согласованном draft-flow.

Первая версия не обязана поддерживать:

- полностью автоматическую публикацию;
- batch generation для большого массива туров;
- сложную оркестрацию промптов;
- агентные сценарии.

## 11. Архитектурные ограничения

- использовать monorepo как базовую организационную модель;
- использовать Docker для dev environment;
- не добавлять бронирование;
- не смешивать admin workflow и public rendering без явного слоя ответственности;
- не строить избыточную инфраструктуру для AI до появления реальной необходимости.

## 12. Definition of Done для первой версии

Первая версия считается готовой, когда:

- можно завести тур через админку;
- можно заполнить фото, описание, длительность, тип и маршрут;
- можно добавить несколько дат и цен;
- тур можно сохранить как `draft` и `published`;
- опубликованный тур виден в публичном каталоге;
- каталог фильтруется;
- поиск возвращает релевантные туры через embedding-based flow;
- администратор может вручную запустить LLM-генерацию и использовать результат;
- публичная часть работает через SSR.
